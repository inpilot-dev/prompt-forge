# prompt-forge

거지 프롬프트를 **맥락에 맞는 GOOD 프롬프트**로 재조립해 주는 Claude Code 스킬 +
성장하는 패턴 라이브러리.

아무렇게나 쓴 한 줄("버그 고쳐줘")을 검증된 프롬프트 패턴(실밸개발자 / 알렉스 16패턴 등)으로
다시 짜서, **복붙 가능한 텍스트**로 돌려준다.

> **철칙: 실행하지 않는다.** 변환된 프롬프트를 코드블록으로 출력할 뿐, 그 안의 작업은
> 수행하지 않는다. 그래서 도구에 독립적이다 — 결과를 Claude Code·Codex·ChatGPT 어디에나 붙여 쓴다.

## 왜

프롬프트 팁은 인터넷에 널렸지만, "지금 이 요청에 어떤 패턴을 써야 하나"는 매번 사람이 판단한다.
prompt-forge는 그 판단을 자동화한다:

- **크기 자동 조절** — 단일 작업(small)엔 3~4개 패턴만, 프로젝트급(large)엔 단계별 풀세트.
  과잉 방지가 1급 요구사항 (작은 일에 8단계 PRD를 붙이지 않는다).
- **엔진은 불변, 재료만 성장** — 새 고수를 조사하면 `patterns/`에 파일 하나가 늘 뿐,
  엔진(SKILL.md)은 그대로다.
- **적용 패턴 항상 명시** — 변환 결과에 "어떤 패턴을 왜 썼는지"를 한 줄로 남겨 학습 루프를 만든다.

## 설치 (스킬 연결)

이 repo 자체가 Claude Code 스킬을 담고 있다. 스킬을 인식시키는 방법:

- **개인 스킬로 연결** — `skills/prompt-forge/`를 Claude Code가 읽는 스킬 경로
  (`~/.claude/skills/`)에 심볼릭 링크하거나 복사한다.
- 연결되면 `/prompt-forge`로 호출되고, `patterns/` · `research/`는 같은 repo 안에서
  스킬이 상대 경로로 참조한다.

> 스킬 본체: [`skills/prompt-forge/SKILL.md`](skills/prompt-forge/SKILL.md)

## 사용법

호출:

```
/prompt-forge <다듬을 프롬프트>
```

또는 그냥 "이 프롬프트 다듬어줘 / 고쳐줘 / forge this prompt" 하고 원본을 던진다.

엔진은 5단계로 동작한다:

1. **크기 판단** — small(단일 작업) / large(프로젝트급)
2. **맥락 검사** — 필수 슬롯이 비었으면 최대 3개까지 역인터뷰.
   3개 넘게 비면 질문 대신 빈칸 `[ ]` 프롬프트를 바로 출력.
3. **패턴 선택** — `patterns/_INDEX.md`를 읽어 이 요청에 맞는 패턴만 고른다.
4. **변환 출력** — 변환된 프롬프트(코드블록) + 적용 패턴 목록(한 줄).
5. **끝** — 실행하지 않는다.

### 예시

**입력:** `버그 고쳐줘` (small)

증상·대상이 불명 → 질문 2개("① 어떤 에러? ② 어느 파일·함수?") → 답을 받으면:

```
[파일:함수]에서 [증상]이 발생한다.
문제: <재현 조건 한 줄>.
고칠 것: 근본 원인 한 곳만 수정. 증상 패치 금지.
완료 판단: <이 입력>이 <이 출력>을 내면 끝. 기존 통과 테스트 깨지지 않을 것.
```

`적용: 문제정의, 검증방법, 범위제한 (small)` — small엔 킥오프·PRD를 붙이지 않는다.

## Repo 구조

```
prompt-forge/
├─ skills/prompt-forge/SKILL.md   ← 엔진 (불변). 5단계 변환 절차
├─ patterns/
│  ├─ 00-silvally-alex.md         ← 기존 16패턴 이식본 (기준선)
│  └─ _INDEX.md                   ← | 단계 | 패턴 | 파일 | 역인덱스
├─ research/
│  ├─ RUBRIC.md                   ← 출처 입장자격 채점기 (상 2개↑만 입장)
│  └─ candidates.md               ← 조사 대상 후보 목록
├─ docs/specs/                    ← 설계 스펙
└─ README.md
```

**단계 분류**(패턴이 붙는 자리)는 9개:
킥오프 / 컨텍스트주입 / 리서치위임 / PRD / 스코핑 / 솔루션깎기 / 검증기 / 구현위임 / 검증루프.

## 라이브러리 키우기

패턴은 조사로 늘린다. 절차:

1. 후보를 [`research/candidates.md`](research/candidates.md)에 올린다.
2. [`research/RUBRIC.md`](research/RUBRIC.md) 4항목으로 채점 — **상 2개 이상만 입장.**
3. 통과 시 프롬프트 원문·원리를 뽑아 `patterns/` 파일 하나를 만든다.
   (조사 1회 = 패턴 파일 1개. 넓게 100개 긁기 금지.)
4. `patterns/_INDEX.md`에 줄 추가. **엔진은 건드리지 않는다.**

## 진화 경로

- **v1 (현재)** — 엔진 + 기존 16패턴 이식 + 조사 루브릭.
- **v1.x** — 조사로 패턴 파일 추가 (엔진 무변경).
- **v2** — 로그 리뷰어. 실제 사용 로그가 2주+ 쌓인 뒤, 같은 `patterns/`를 읽는 두 번째 스킬.
- **v3** — 플러그인화 (선택).
