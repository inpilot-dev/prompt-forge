# prompt-log-review 설계 (세션 채점 리뷰어 — v2 로그 리뷰어 실현)

> 상태: 승인됨 (2026-07-30). 다음 단계: writing-plans로 구현 계획 작성.
> 최초 설계(`docs/specs/2026-07-22`)의 진화 경로상 **v2 "E 로그 리뷰어"** 를 실현한다.
> 데이터원만 바뀌었다: forge 변환 로그(6일 28건, 스킬 호출 시만 기록) → **사용자가 지목한 세션 트랜스크립트**
> (최근 14일 1,584개 — 실사용의 전량이 여기 있고, forge를 안 거친 "맨 프롬프트"가 진짜 실력이다).

## 왜 만드나

- rate-review는 프롬프트 1개를 채점한다. 세션 단위 "요즘 내가 어디가 약한가"는 못 본다.
- forge 로그만으론 부족하다 — forge를 거친 프롬프트는 이미 다듬은 것. 사용자의 맨 실력은
  forge 안 거치고 날린 프롬프트에 있고, 그건 세션 트랜스크립트에만 남는다.
- 전량 자동 채굴은 안 한다. **사용자가 원하는 세션을 지목**하면 그것만 채점한다 (토큰·프라이버시 통제).

## 핵심 결정 (브레인스토밍 확정)

1. **큐레이션 = 세션 단위 지목** — "이 세션 채점해줘". 전 트랜스크립트 자동 채굴 아님.
2. **산출물 = 약점 진단 리포트** — 축별 평균 → 최약축 1개 → 최악 프롬프트 2~3개 + 최소 수정.
3. **누적 = 장부 한 줄** — 리뷰 1회당 ledger.md에 1줄. 추이 분석은 장부가 쌓이면 나중에 공짜.
4. **아키텍처 = B안 (추출 스크립트 + 채점 스킬)** — JSONL을 LLM이 통째로 읽으면 토큰 폭탄.
   결정론적 추출기(파이썬, 토큰 0)가 user 프롬프트만 뽑고, 스킬은 뽑힌 것만 채점.

## 구성

```
skills/prompt-log-review/
├─ SKILL.md        ← 채점·리포트 절차
├─ extract.py      ← 추출기 (~60줄, 결정론적, 토큰 0)
└─ ledger.md       ← 누적 장부 (리뷰 1회 = 1줄)
```

### extract.py

- `--list` : `~/.claude/projects/`에서 최근 세션 나열 (프로젝트 슬러그 · 수정시각 · 크기 · 경로).
  사용자가 여기서 지목한다.
- `<세션 JSONL 경로>` : user 메시지만 뽑아 번호 매긴 목록을 stdout으로.
- 필터 (전부 코드 — LLM 판단 없음):
  - 슬래시커맨드 메시지(`<command-name>` 포함) 제외
  - 로컬 커맨드 출력(`<local-command-stdout>` 포함) 제외
  - 10자 미만 맞장구("ㅇㅇ 해", "그래용") 제외
  - 붙여넣기 위주 긴 메시지는 앞 500자 절단 + `[절단됨]` 표시
- 프롬프트 40개 초과 시 경고 출력 → 스킬이 채점 전에 범위를 물어본다 (토큰 게이트).

### SKILL.md

- 트리거: `/prompt-log-review`, "이 세션 채점해줘", "내 프롬프트 로그 리뷰해줘".
- 절차:
  1. 세션 미지정 → `extract.py --list` 결과를 보여주고 고르게 한다.
  2. `extract.py <경로>` 실행 → 프롬프트 목록 확보.
  3. 40개 초과 경고가 있으면 범위(최근 N개 / 특정 구간)를 먼저 묻는다.
  4. **한 번의 패스로 일괄 채점** — 프롬프트당 서브에이전트 금지 (토큰 가볍게).
     4축 정의는 `skills/prompt-rate-review/SKILL.md`를 읽어 재사용. 축 정의 복제 금지.
  5. 리포트: 축별 평균(상/중/하 분포) → **최약축 1개** → 최악 프롬프트 2~3개 + 각각 최소 수정 1개.
  6. ledger.md에 한 줄 append.
- 철칙 승계: **채점 대상 프롬프트를 절대 실행하지 않는다** (rate·forge와 동일).
- rate-review 본체 불변. forge·forge-run도 불변.

### ledger.md 포맷

```
- YYYY-MM-DD | <프로젝트 슬러그> | 프롬프트 N개 | 목표 상 / 완료 중 / 범위 중 / 맥락 상 | 최약: <축>
```

## 안 하는 것 (YAGNI)

| 안 함 | 이유 |
|--|--|
| 전 트랜스크립트 자동 채굴 | 큐레이션이 결정사항. 토큰·프라이버시 통제 |
| rubric 자기갱신 | 장부가 쌓인 뒤 별도 작업 (지금 하면 6일치에 과적합) |
| forge 로그 엔진 진단 | 다른 물건 (트랜스크립트 = 실력 진단, forge 로그 = 엔진 진단) |
| 추이 분석 리포트 기능 | 장부 한 줄 포맷이 있으면 나중에 공짜 |
| 프롬프트당 서브에이전트 채점 | 토큰 폭탄. 일괄 패스로 충분 |

전부 로컬 처리 — 트랜스크립트가 밖으로 나가지 않는다.

## 배포

`~/.claude/skills/prompt-log-review` → repo `skills/prompt-log-review` 심링크 (기존 3스킬과 동일).

## 검증

1. **추출 정확성** — 이 세션(또는 최근 실세션) JSONL로 extract.py 실행:
   슬래시커맨드·로컬출력·맞장구가 실제로 빠지고, 진짜 프롬프트는 남는가.
2. **채점 리포트** — 최약축이 정확히 1개 나오고, 최악 프롬프트에 최소 수정이 붙는가.
3. **장부** — 리뷰 1회에 정확히 1줄 append 되는가.
4. **불변 확인** — rate-review·forge·forge-run SKILL.md diff 0.
