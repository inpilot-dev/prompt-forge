# rate → forge → rate 교차검증 1회 실측 (2026-09-01)

README가 내세우는 "채점축 ↔ forge 슬롯 정합이라 `rate → forge → 다시 rate`로 점수가
오르는지 교차검증된다"는 클레임의 첫 실행 기록. 대상은 `skills/prompt-rate-review/test-prompts.md`
픽스처 5케이스 전부. 역인터뷰 응답자가 없으므로 forge는 스펙대로 **무응답 → 빈칸 `[ ]` 출력** 경로를 탔다.

방법: rate-review SKILL.md의 축 정의표를 원문 그대로 기계 적용(상/중/하 판정 근거를 각 축 정의 문구에 대응).
검증 런이므로 `logs/`에는 기록하지 않았다(사용 통계 오염 방지).

## 발견 — 상승에는 두 층이 있다

1. **forge가 자체 문구로 채우는 축은 하→상까지 오른다.** 범위제한("근본 한 곳만·광범위 수정 금지"),
   완료판단의 틀("기존 테스트 유지"), 실데이터강제("추정 금지") 같은 패턴 문구는 사용자 입력 없이도 실값이다.
2. **사용자 값이 필요한 축은 빈칸이 남는 한 중에서 멈춘다.** 슬롯 구조는 생겼지만 값이 없으므로
   "방향은 있으나 모호"(중)가 상한. 빈칸을 채우면 상으로 오르는 구조다.

즉 클레임은 성립하되 정밀한 문장은 이렇다: **"forge는 하를 없애고, 빈칸 충전이 상을 만든다."**
빈칸 미충전 상태의 중-상한은 버그가 아니라 철칙(멋대로 채우지 않는다)이 만드는 의도된 천장이다.
